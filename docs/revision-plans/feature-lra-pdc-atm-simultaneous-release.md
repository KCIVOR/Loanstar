## Background

Revision Tracker 2, Item 4: LRA currently must pick exactly one release method — PDC (checks) or ATM Surrender (cash) — via a single dropdown. Some borrowers are required to provide both simultaneously. LRA needs to select both on the same loan, with details for each collected and recorded, both visible to AR at transmittal, and document generation producing documents for both methods. At least one method is required; the borrower never chooses.

## Audit findings (verified 2026-08-14)

**This is a substantially larger change than the CIG items** — `release_path` is not an isolated field, it's a single-value column (`text CHECK (release_path IN ('with_pdc','without_pdc'))`, `supabase/migrations/20260706160000_p6_lra_release.sql:7`) that ~16 files read as a scalar via exact equality (`=== "with_pdc"`) or as an object/lookup key (`AUTO_GENERATED_SLUGS[releasePath]`). None of it is structured as a set today. A real schema change is required, not an additive one.

- **Full `release_files` schema** (`20260706160000_p6_lra_release.sql:3-26`): `release_path text CHECK(...)`, `atm_bank_name text`, `atm_card_last4 text` — **no `atm_account_number` column exists anywhere**, confirmed via grep across every consumer (`src/lib/ar/masterlist.ts`, `src/lib/lra/blockers.ts`, the LRA page). The request's "bank, account number, ATM card info" is not fully supported by the current schema even for a single ATM-only release — this plan adds the missing column regardless of "both."
- **`setReleasePath()`** (`src/lib/lra/release-service.ts:81-157`, read in full): takes a single `path: ReleasePath`, requires ATM fields only `if (path === "without_pdc")`, writes `release_path`/`status`/`atm_bank_name`/`atm_card_last4` in one `.update()`, computes `nextStatus` (`with_pdc → "pdc_encoding"`, else `"ready_generate"`), calls `ensureDocumentSlots` twice (once for `releaseStageForPath(path)`, once for the constant `"release"` stage). For two paths, `nextStatus` must still route through `pdc_encoding` whenever PDC is one of the selected paths (the extra step), and `ensureDocumentSlots` needs to seed both signing stages, not one.
- **`AUTO_GENERATED_SLUGS`** (`src/lib/lra/constants.ts:13-32`, full object): `with_pdc` and `without_pdc` share 5 of 7 slugs (`blri`, `promissory_note`, `disclosure_statement`, `letter_of_intent`, `loan_agreement`); only the voucher pair differs (`check_voucher`/`ar_check_voucher` vs `cash_voucher`/`ar_cash_voucher`). `generateReleaseDocuments()` (`release-service.ts:265-392`) does `const slugs = AUTO_GENERATED_SLUGS[releasePath]` (`:292`) — a scalar lookup. For "both," this becomes a union (dedup via `Set`, same pattern `allAutoGeneratedSlugs()` at `constants.ts:35-40` already uses) so both voucher pairs get generated alongside the 5 shared docs once.
- **`buildReleaseTemplateContext()`** (`src/lib/lra/template-context.ts:109-118`): `templateContext` is built **once per whole release** in `generateReleaseDocuments` (`release-service.ts:309-326`, hoisted above the slug loop) and picks `disbursementCode`/`disbursementLabel` (`"1100115"`/`"Bank"` vs `"1100110"`/`"CASH"`) from a single `isCheck = releasePath === "with_pdc"` boolean. Only the two voucher-pair slugs actually consume `disbursementCode`/`disbursementLabel` — the 5 shared slugs don't reference disbursement fields. For "both," this needs **two contexts** (one `isCheck: true`, one `isCheck: false`), with the voucher-pair slugs rendered against the matching context and the 5 shared slugs rendered once against either (they're path-independent).
- **`pdc-collect.ts`** (read in full, `src/lib/lra/pdc-collect.ts`): every gate (`canConfirmPdcCollection:43-49`, `assertCanConfirmPdcCollection:51-64`, `closeRequiresPdcCollection:66-70`, `assertPdcCollectedForClose:72-80`, `maybePdcCollectBlocker:87-96`) does `releasePath !== "with_pdc"` / `=== "with_pdc"` as an **exact-match gate**. These become membership checks (`releasePaths.includes("with_pdc")`) — the semantics don't change (physical PDC collection is still required whenever PDC is one of the selected methods, "both" doesn't remove that requirement), only the comparison operator.
- **Confirmed pre-existing gap, out of scope for this plan**: `REQUIRED_SIGNED_RELEASE_SLUGS` (`release-service.ts:669-673`) hardcodes `signed_check_voucher` — there is **no `signed_cash_voucher` document type anywhere** in `document_types` seed data (grepped `supabase/migrations/*.sql` for both strings — only `signed_check_voucher` exists, seeded at `20260706120002_p2_seed_documents.sql:33,101`). This means `without_pdc`-only releases have never had a working signed-voucher close-gate (matches the existing tracker note on Item 9 in `system-revision-report-tracker.md`: "Zero `release_files` rows with `release_path='without_pdc'` exist in the DB, so this has never been exercised" — a previously-found, already-deferred bug). **Decision for this plan**: when both paths are selected, `closeRelease()` requires the same signed slugs `with_pdc` alone requires today (i.e., do not add a `signed_cash_voucher` requirement) — this keeps a "both" release closeable using existing, working infrastructure, and does not silently expand scope into fixing the separately-tracked, already-deferred without_pdc-closing gap. If the client wants that fixed too, it's a separate item.
- **UI is a single-select `<Select>` dropdown, not checkboxes** (`src/app/lra/applications/[id]/page.tsx:755-799`), state `useState<"with_pdc"|"without_pdc">("with_pdc")` (`:143-144`), POST body `{ releasePath, atmBankName, atmCardLast4 }` (`:258-264`) matching the API's current single-enum zod schema (`src/app/api/lra/applications/[id]/path/route.ts:16`). ~8 more single-value conditionals exist further down the same file (PDC-encoding card visibility `:802`, close-gating booleans, path label, pipeline stepper input) — full list in Phase 6.
- **AR's copy**: `src/lib/ar/masterlist.ts:131-133` copies `release_path`/`atm_bank_name`/`atm_card_last4` straight from `release_files` onto the new `masterlist` row at AR-receive time; `masterlist` has its own mirrored columns (`supabase/migrations/20260707000000_p7_ar_collection.sql:37-39`) with the same single-value shape; `masterlistToExportRow()` (`src/lib/ar/masterlist.ts:346-351`) re-exports them into every CSV row — this is the literal "visible to AR when transmitted" surface named in the spec, and needs the same array widening.
- **Borrower-facing, read-only**: `src/app/api/borrower/applications/[id]/release-documents/route.ts` and `src/app/borrower/applications/[id]/page.tsx` read `release_path` to pick which signing stage to show the borrower — per the spec ("borrower does not choose the method"), these only need to keep working (show whichever stage(s) apply), not gain any new interactivity.

## Scope decision — schema approach

**`release_files.release_path` (scalar) is replaced by `release_files.release_paths text[]`** (array of `'with_pdc' | 'without_pdc'`, 1 or 2 elements), same treatment mirrored onto `masterlist.release_paths`. A new `atm_account_number text` column is added to both tables (missing today, needed regardless of "both"). This is a genuine breaking change to a column ~16 files read — **staged across phases, not a single big-bang cutover**:

- **Phase 1** adds the new array + account-number columns and backfills the array from the existing scalar (`ARRAY[release_path]` where not null). The legacy scalar columns (`release_path`, and the existing `atm_bank_name`/`atm_card_last4`) are **kept in place, not dropped**, so nothing breaks mid-migration while later phases catch up.
- **Phases 2–7** migrate every consumer (lib functions, routes, UI, AR export, borrower-facing reads) to read/write `release_paths` exclusively.
- **Phase 8** drops the legacy `release_path` scalar column from both tables, once every phase is validated — the final cutover, done last and only after live confirmation nothing still depends on the scalar.

Eight phases total: DB foundation, path-setting + validation, document generation, PDC-collection/close gating, stage/pipeline functions, the LRA UI itself, AR + borrower-facing consumers, then the legacy-column cleanup.
